Dust2Glow - Cleaning Service Management System

Welcome to the official system documentation for Dust2Glow, an enterprise-grade Cleaning Service Management Platform built on PHP 8.2+ and Laravel 12. This documentation covers system installation, architecture, role management, customer booking workflows, wallet/reward engines, and administrative controls.

System Architecture Highlights

  • Backend Framework: PHP 8.2+ / Laravel 12 with Fortify authentication and Sanctum API security.
  • Frontend Stack: Responsive Blade Templates, Bootstrap 4, jQuery, Yajra DataTables, and SweetAlert2.
  • Database: MySQL 8.0+ with transactional integrity, foreign keys, and migration-driven schema management.
  • Role Security: Granular access control using Middleware guards (`can:admin`, `can:customer`, `can:view-audit-logs`).
  • Testing Suite: Automated PEST unit and feature test suite with 100% assertions coverage for critical modules.

Server Requirements

Ensure your Web Server (Apache or Nginx) satisfies the following server environment specifications:

Component Requirement Notes
PHP Version PHP 8.2.0 or higher Recommended: PHP 8.3 / 8.4
PHP Extensions BCMath, Ctype, Fileinfo, JSON, Mbstring, OpenSSL, PDO, PDO_MySQL, Tokenizer, XML Required for Laravel 12 core and Yajra DataTables
Database Server MySQL 8.0+ or MariaDB 10.5+ InnoDB storage engine with UTF8MB4 charset support
Web Server Nginx 1.20+ or Apache 2.4+ URL rewriting (`mod_rewrite` on Apache) enabled

Authentication & Security

The authentication layer provides secure access for administrators, sub-admins, and customers with strict role separation.

Role ID Role Name Default Dashboard Permissions & Boundaries
Role 1 Admin / Sub-Admin /admin-dashboard Full access to services, bookings, customers, sub-admins, settings, audit logs, and rewards.
Role 2 Customer /dashboard Booking wizard access, personal wallet, referral tracking, profile management, and review rewards.

Security Features

  • Email Verification: Unverified customers are redirected to /email/verify until email link is confirmed.
  • Welcome Credit Bonus: Verified customers automatically receive welcome wallet credits if enabled in settings.
  • Password Reset Flow: Secure tokenized email links via /forgot-password and /reset-password/{token}.

Booking Service Working Flow

The Booking Service Working Flow guides customers through an intuitive, multi-step booking process, seamlessly connected with administrator review, status approval, and final checkout confirmation.

Booking Journey Overview

Phase / Step User Action System State & Functionality
Step 1 Booking Details & Options Customer selects cleaning service category, cleaning frequency, room parameters, and additional extra options.
Step 2 Date & Time Selection Customer chooses an available cleaning date from the calendar and selects an available arrival time window.
Step 3 Review & Request Submission Customer verifies contact info, address details, and submits booking request. System sets status to Pending Approval and notifies Administrator.
Admin Approval Administrative Verification Administrator reviews request, checks schedule capacity, and updates booking status to Approved. Customer is notified.
Step 4 Final Review, Discounts & Payment Customer opens Step 4 checkout from My Bookings, applies promo codes or wallet credits, and completes payment confirmation. Status updates to Confirmed.

Step 1: Booking Details & Service Selection

The customer initiates a booking request by selecting their desired cleaning service, service frequency (one-time, weekly, bi-weekly, or monthly), property layout specifications (bedrooms, bathrooms), and customized extra add-on services.

  • Service Selection: Choose primary cleaning package (e.g. Deep Cleaning, Standard Residential Cleaning, Move-In/Out).
  • Frequency Discounting: Recurring frequencies automatically apply frequency percentage discounts.
  • Property Specifications: Select number of rooms, bathrooms, and additional living areas.
  • Extra Add-Ons: Option to select extra services like inside oven cleaning, interior window washing, or carpet steaming.

Step 1: Service & Extra Options Selection

Step 2: Date & Time Slot Selection

The customer picks a convenient date and arrival time window for their cleaning service appointment.

  • Interactive Calendar: View available dates with real-time blackout date and holiday checking.
  • Time Slot Arrival Windows: Select morning, afternoon, or specific shift time slots based on staff availability.
  • Advance Notice Rules: Enforces system lead-time rules so bookings cannot be made without sufficient advance notice.

Step 2: Calendar & Time Slot Picker

The customer verifies their personal contact details, cleaning service address, special access instructions (e.g. key location, gate codes), and reviews the preliminary cost summary before submitting the booking request.

  • Contact & Address Review: Uses saved user profile address or allows manual entry of service location.

Booking Operations & Operational Scenarios

Administrative management of customer bookings, lifecycle status transitions, and special operational case scenarios.

Booking Lifecycle States

Status Badge Stage Description & Action Trigger
Pending Initial Submission Request submitted by customer (Step 3 completed). Awaiting administrator verification.
Approved Admin Verified Administrator approved appointment time & team availability. Customer can now proceed to Step 4.
Confirmed Paid / Locked Customer completed Step 4 checkout & payment. Appointment is locked into cleaner dispatch schedule.
Completed Job Finished Cleaning service physically performed. Automatically awards referral bonuses if applicable.
Cancelled Terminated Booking cancelled by customer or administrator. Releases schedule time slot.

Operational Case Scenarios

Scenario 1: Standard Approval & Payment Flow (Happy Path)
  1. Customer creates booking through Step 1, Step 2, and Step 3 -> System records booking as Pending.
  2. Administrator receives notification -> Inspects request and clicks Approve -> Status becomes Approved.
  3. Customer receives notification -> Opens My Bookings -> Clicks Proceed to Step 4.
  4. Customer completes Step 4 checkout -> Status updates to Confirmed.
  5. Admin receives confirmation alert -> Cleaning crew is assigned and dispatched.
Scenario 2: Promotional Code & Wallet Credit Application
  1. Customer earns wallet credits via Welcome Bonus, Referral Rewards, or Google Review Rewards.
  2. During Step 4 checkout, customer enters a promotional code (e.g. WELCOME15) and toggles wallet credit redemption.
  3. System verifies coupon validity and wallet balances, deducting savings from final cost before payment.
Scenario 3: Schedule Conflict & Admin Cancellation
  1. If a customer requests a date/time slot that encounters staffing shortages or emergency blackout periods, Administrator updates status to Cancelled or contacts customer to adjust timing.
  2. Customer receives cancellation notification explaining the update.
Scenario 4: Cleaning Completion & Automated Referral Payout
  1. Upon completion of the cleaning job, Administrator marks booking as Completed.
  2. If the customer was referred by an existing user, the system automatically deposits the referral reward bonus into the referrer's wallet.

System Settings & Feature Toggles

The System Settings page (/settings) allows Administrators to configure core company identity, operational booking rules, currency settings, reward values, and feature toggles in real-time.

System Settings Control Panel

Detailed Settings Configuration Guide

1. Company Identity & Branding
  • Company Name: Official business name displayed on customer receipts, page titles, and email templates.
  • Company Logo: Upload brand logo (PNG, JPG, WEBP, SVG). Dynamically updates header logo, sidebar, and documentation branding upon upload.
  • Phone & Email: Primary customer support hotline and contact email address.
  • Address: Physical address or headquarters location displayed on invoices.
2. System Timezone & Currency
  • Timezone: Sets the runtime PHP and Laravel timezone (e.g. America/New_York, Australia/Sydney). All booking calendar slots, daily schedules, and audit log timestamps evaluate against this setting.
  • Currency: ISO currency code and symbol (e.g. USD, $) formatted across pricing displays, totals, and wallet credits.
3. Operational Booking Rules
  • Minimum Booking Amount ($): Minimum cart total required before a booking can be placed.
  • Max Wallet Usage ($): Maximum dollar credit amount a customer can redeem from their wallet balance per single booking.
  • Maximum Advance Booking Days: Restricts how far into the future (e.g. 30 days) customers can schedule cleanings on the booking calendar.
  • Cancellation Notice (Hours): Minimum hours notice required (e.g. 24 hours) for free customer cancellations.
4. Rewards & Feature Toggles
  • Welcome Credit ($) & Toggle: Automated wallet bonus awarded to new customers upon completing email verification.
  • Referral Reward ($) & Toggle: Automated wallet bonus awarded to a referrer when their invited friend completes their first cleaning booking.
  • Google Review Reward ($) & Toggle: Master toggle and credit amount awarded to customers when an admin approves their Google Review reward request.
5. Promotions & Coupon Restrictions
  • Promotion Max Uses: System-wide default total redemption limit for new promotional codes.
  • Promotion Max Uses Per Customer: Maximum times an individual customer can redeem the same promotion (default: 1).

1. Promotions List Interface (Overview)

Access Promotions from the main administration sidebar menu to view all active, inactive, and expired promotional codes.

  • Promo Code & Name: Highlights the unique uppercase coupon code and descriptive offer title.
  • Discount Details: Displays fixed dollar amount savings (e.g. $15.00 Off) or percentage discounts (e.g. 10% Off).
  • Customer Eligibility Scope: Indicates whether the coupon applies to All Customers, New Customers Only, or Existing Customers Only.
  • Validity Window: Shows start date/time and expiration date/time.
  • Status Indicators: Color-coded badges indicating Active, Inactive, or Expired promo codes.

2. Add Promotion - Fixed Dollar Discount ($)

To create a new promotional code with a fixed dollar discount:

  1. Click the "+ Add Promotion" button at the top-right of the Promotions page.
  2. Enter an internal Promotion Name and a unique Promo Code (e.g. WELCOME15).
  3. Select Fixed under Discount Type. The discount value field automatically switches to display a dollar sign ($) prefix.
  4. Enter the discount amount (e.g. 15.00).
  5. Set the Start Date & Time and Expiration Date & Time.
  6. Choose the Customer Eligibility Scope:
    • All customers: Open to any registered user.
    • New customers only: Restricted to first-time bookings.
    • Existing customers only: Restricted to returning clients.
  7. Click "Save Promotion" to create the offer.

Add Promotion Modal - Fixed Dollar Discount

3. Add Promotion - Percentage Discount (%)

To create a promotional code that calculates a percentage discount based on the booking service total:

  1. Open the "+ Add Promotion" modal form.
  2. Select Percentage under Discount Type. The discount input field dynamically updates to show a percentage sign (%) suffix.
  3. Enter the percentage value (e.g. 10 for a 10% discount off total booking cost).
  4. Configure the code name, validity dates, status, and eligibility rules.
  5. Click "Save Promotion" to finalize.

Add Promotion Modal - Percentage Discount

4. Edit Promotion Details

To update an existing promotional code:

  1. Find the promo code row in the Promotions list table.
  2. Click the Edit button (pencil icon) under the Action column.
  3. The Edit Promotion Modal will appear pre-filled with all existing code settings.
  4. Modify any desired values, such as extending the expiration date, adjusting discount amounts, or changing customer eligibility.
  5. Click "Update Promotion" to save changes.

Edit Promotion Details Modal

5. Delete Promotion

To remove an unnecessary or redundant promotional code:

  1. Click the Delete button (trash icon) on the target promotion row.
  2. A confirmation alert will prompt: "Are you sure you want to delete this promotion?"
  3. Confirming the prompt permanently deletes the promotion code record from the system.

6. Booking Checkout Integration (Customer Redemption)

Customers can apply active promo codes during Step 4: Review & Confirm of the cleaning booking wizard:

  1. During booking checkout, the customer locates the Promotions & Discount Code input box.
  2. The customer types their promo code and clicks Apply.
  3. The system validates the code against all configured rules:
    • Verifies the code exists and is marked as Active.
    • Ensures current date/time is within the Start Date and Expiration Date window.
    • Confirms customer eligibility (e.g. checking first-time booking status if code is restricted to New Customers Only).
    • Checks system minimum booking order thresholds.
  4. Upon successful validation, the calculated discount (fixed dollar or percentage) is applied immediately, reducing the final total price card on screen.

The Audit Logs module (/audit-logs) provides an automated security and activity tracking system that records user actions across the platform for complete operational transparency.

1. Audit Logs Overview List Page

Access Audit Logs from the main admin sidebar (/audit-logs) to view recorded activity logs.

  • Activity Log Columns: Displays User Name, Action Event (e.g. Created, Updated, Deleted), Target Model (e.g. Booking, Service, SubAdmin), IP Address, Timestamp, and View Details button.
  • Search & Filter: Live search allows filtering logs by user name, action type, or IP address.

Audit Logs Overview Page

2. Audit Log Details View Modal

To inspect full details and attribute changes for any specific activity record:

  1. Click the View button (eye icon) on any audit log row.
  2. The Audit Log Details Modal will open displaying:
    • User Details: User name and email address who performed the action.
    • Event Action & Target: Specific action type (Created, Updated, Deleted) and affected system module.
    • Network Metadata: User IP address and Browser User-Agent string.
    • Old Values vs New Values Comparison: Side-by-side or line-by-line diff showing original data attributes before the change versus new data attributes after the change.
    • Timestamp: Exact date and time the event occurred.
